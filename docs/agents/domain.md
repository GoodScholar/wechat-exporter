# Domain Docs

本仓库采用 single-context（单上下文）布局。

## 探索代码前

- 如根目录有 CONTEXT.md，先阅读其中的领域术语和约定。
- 如有 docs/adr/，阅读与当前任务相关的架构决策。
- 将来如引入 CONTEXT-MAP.md，按其指引阅读与当前主题相关的上下文文档，并更新本配置。

这些文件尚不存在时，直接继续，不报告缺失，也不提前建议创建。后续由 domain-modeling 技能在术语或决策明确时按需创建。

## 文件布局

- CONTEXT.md：项目领域术语和约定。
- docs/adr/：项目架构决策，例如 0001-<decision>.md。
- src/：实现代码。

## 术语一致性

Issue 标题、重构建议、诊断假设和测试名称中的领域概念，应使用 CONTEXT.md 定义的术语，避免使用文档明确排除的同义词。

缺少相关概念时，判断它是否属于项目实际使用的语言；确认存在缺口后交由 domain-modeling 处理。

## 决策冲突

拟议方案与已有 ADR 冲突时，明确指出相关 ADR 及重新讨论的理由，不静默覆盖已有决定。
